## Deterministic final transport repair

No further paid API spend was authorized after the collector-4 revalidation.
The four INFRA snapshots above remain unchanged as the result measured at
`28550e55c4ee`; they are not rewritten after the repair.

The existing `rich-0002` reproduction showed the candidate's private artifact
directory still lived in the same container mount namespace as the protected
workspace overlays. Docker copy recursively walked the workspace-facing
single-file overlay and failed before host admission. The bounded repair in
`d22d7cb` and `610491e` changes transport, not evidence admission:

This is a deterministic transport repair of that copy boundary, not a change
to weights, thresholds, detectors or evaluation inputs.

- each `run_capture` creates one fresh Docker-managed artifact volume and
  mounts it only at `/tmp/skeptic-artifacts` in the candidate;
- every negative Docker-client exit is treated as uncertain, and a bounded
  successful `docker stop` is required before helper creation or copy-out;
- one read-only helper exposes only the stopped artifact volume, is never
  started, and provides no route to `/workspace`, protected inputs or host
  paths;
- candidate container, helper and volume cleanup is attempted on every
  partial-success and failure path under the existing shared operation
  deadline; and
- `docker cp` establishes no trust. Its output still enters the existing
  descriptor-relative no-follow admission layer, typed byte caps and
  create-exclusive host sealing.

The first zero-API working-tree sweep is preserved at
`evals/v1/revalidation/rich-0002-transport/runs/eval-20260901-000455`.
Because its manifest necessarily names the pre-commit HEAD `535b337e7a0d`, a
second identical deterministic sweep was run after the transport commits and
is the authoritative commit-addressable proof:
`evals/v1/revalidation/rich-0002-transport-final/runs/eval-20260901-002319`,
verifier `aed81a193d06`, collector 4. Both runs used the deterministic profile
with `ANTHROPIC_API_KEY` removed and spent $0. Both produced the same four
outcomes with 0 INFRA:

- `rich-0002/gold`: PASS 0.00;
- `rich-0002/gold-prime`: PASS 0.00;
- `rich-0002/h5`: SUSPECT 1.65; and
- `rich-0002/h10`: FAIL 0.00.

The independent reviewer found one gap in the first transport commit: a
negative Docker-client result other than the timeout sentinel could have
bypassed explicit stop confirmation. `610491e` generalizes the condition to
every negative exit and adds `-9` success and fail-closed regressions. The
scoped re-review approved the repair with no remaining blocking finding.
