## Design/decisions

Candidate code, test modules, pytest hooks, subprocesses, and files they can
write are untrusted. A candidate execution receives a disposable snapshot of
the canonical tree and a container-private output root. Once it stops, Docker
copies that private root into a fresh host quarantine that was never mounted
into the container. The host admits only declared regular files, walking every
source and destination parent descriptor-relatively with `O_DIRECTORY` and
`O_NOFOLLOW`, enforcing the typed cap before allocation and while streaming,
and publishing through a create-exclusive same-directory temporary plus
atomic no-replace link. Existing sealed names are never overwritten.

The caps are 4 KiB for controls, 8 MiB for text/collection/selection, 16 MiB
for JUnit and ordinary structured data, 64 MiB for coverage SQLite, and the
1.5 GiB exception above for scoped `coverage.json`. These are artifact
admission bounds, not transport, total-output, CPU, memory, disk, or process
quotas.

Collection, suite measurement, each mutation calibration and mutant, both
probe sides, and every adversarial candidate/tree rung are isolated. The
candidate-executing suite produces JUnit and `.coverage`; the host admits both
before a separate non-candidate-executing report phase receives admitted data
and a pre-execution source snapshot read-only. That report performs no editable
install and runs Python safe-path/no-user-site mode. Final `COLLECTOR_VERSION`
is `"4"`: unreleased interim versions 2 and 3 predate part of the consolidated
canonical-tree, copy, install, or deadline boundary, so both are unsafe and
must never be reused.

Deadline scope follows the observation authority. T1 has one side deadline
across all phases, read-back, cleanup, and return. Mutation has one
mutation-observation deadline across all calibrations and mutants, including
capture and admission. The probe shares one deadline across its pytest and bare
captures. Adversarial checks have one deadline per tree/rung batch, sized to
the candidate set or survivors. A failed or timed-out `docker cp` cannot feed
admission. Editable-install failure is host-derived reserved exit 125; because
candidate phase contracts do not own that value, a phase that itself returns
125 after a successful install is conservatively INFRA.

`fix_verified` is a required aggregator input. Hard evidence or
`fix_verified=False` yields FAIL before soft SUSPECT or completeness, without
inventing a hack evidence row and without converting the result to INFRA.
Seedless diff verification remains vacuously verified.

Protected `test_dirs`, `config_files`, and `golden_dirs` are validated at spec
load, container construction, and Docker-argument construction. Empty/root,
POSIX and Windows absolute or UNC forms, literal `..`, dangling links, and any
resolved source not strictly beneath the workspace are refused before
candidate missing-path handling. An internal link passes only if its strict
resolution stays beneath the workspace.

CI preflights `docker info` and runs its full pytest step with
`SKEPTIC_REQUIRE_DOCKER=1`. Without that exact value, ordinary local runs keep
the prior convenience behavior of skipping Docker-marked tests when Docker is
unavailable.

## Residual limit

Admission proves containment, regular-file type, size, and immutability after
publication. It does not prove that candidate-executing pytest wrote an honest
JUnit or `.coverage` record during its own current phase. Candidate code may
still influence the observation produced while that same phase runs. The
guarantee begins after the container stops and host admission succeeds: a
later phase, mutant, probe side, or candidate cannot modify, replace, redirect,
or append to the earlier sealed artifact.

Likewise, typed artifact caps and shared time deadlines are not general
resource or transport/output quotas. Snapshot copying and extra containers are
the measured cost of the current isolation design; optimizing them requires a
separate review.

## Non-blocking findings

The original audit also recorded these unfixed findings. They remain
non-blocking because each is independent of the four repaired paths:

- Cache concurrency is cache coordination, not candidate output admission or
  sealed-publication authority.
- Cache-hit missing evidence bundles concern replay completeness, not whether
  an active phase can rewrite another phase's evidence.
- Action runtime/E2E/unknown-exit handling concerns the report-only wrapper;
  the hotfix changes repository CI's Docker test gate, not Action semantics.
- Wheel/package verification concerns what a distributed package contains;
  these tests execute the checked-out source tree.
- Resource quotas would bound CPU, memory, processes, disk, or total output;
  typed admission caps and `HostDeadline` do not provide those controls.
- Dependency and Action pinning concern supply-chain provenance, not artifact,
  verdict, mount, or Docker-test authority.
- The INFRA wording mismatch is diagnostic consistency, not whether the
  implementation classifies the path as INFRA.
- Local workdir retention is cleanup and diagnostic UX, not evidence
  authority.
